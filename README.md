# 精卫填海 · 海岸远行

Godot 4.7.2 / GDScript 的单机 3D 增量游戏原型。从大陆海岸出发，拾石、与穿山甲一起开山、寻找神器，用一次次投石完成精卫自己的心愿。

## 开始试玩

当前提供 **Windows 64 位临时试玩版：源码 + 随附 Godot 4.7.2 引擎**，无需另行安装 Godot。

1. 将仓库 ZIP **完整解压**到文件夹，不能在压缩包里直接双击启动。
2. 双击 **Play.cmd**。首次会自动解压 Godot 文件夹里的引擎，再导入脚本和音频，随后启动游戏；请等待准备完成。

Godot 文件夹内约 84 MiB 的 ZIP 是随项目提供的引擎，启动时无需联网下载。解压后的 EXE 保存在同一文件夹，下次直接复用。请使用可写入的目录；这是包含编辑器引擎的临时版本，尚非正式导出的独立游戏 EXE。引擎采用 MIT 许可，版权及第三方声明见 Godot/LICENSE.txt、Godot/COPYRIGHT.txt 和 [Godot 许可说明](https://godotengine.org/license/)。

其他入口：

- **Open-Editor.cmd**：打开编辑器；也可在 Godot 中导入 project.godot，等待导入完成后按 F5。
- **Test.cmd**：先导入，再运行规则、存档、场景、音效和界面检查，使用独立测试存档目录。
- 支持 GODOT_EXE 环境变量、PATH 中的 godot / godot4，或 `Play.cmd -GodotPath "D:\Godot\Godot_v4.7.2-stable_win64.exe"` 指定引擎。
- 如原工作区旁有 RainyArrow 的引擎，可作为最后的可选查找位置；独立下载不依赖它。

**启动失败排查**：提示引擎缺失或压缩包损坏时，请重新完整下载解压，确保 Godot 文件夹里的 ZIP 存在。也可从 [Godot 官网](https://godotengine.org/download/windows/) 下载标准版 Windows 引擎，并通过上面的 GodotPath 参数指定。`JWState` 找不到、音频 `.sample` 缺失通常意味着没有进行首次导入，请使用更新后的 Play.cmd。失败窗口会保留错误，完整信息位于 artifacts/startup-import.log 或 artifacts/game-launch.log。将错误文字发给开发者即可定位。

开发时可用 `Play.cmd -Check -NonInteractive` 检查自动解压、导入和主场景启动（不打开游戏窗口、不读取正式存档）。随附引擎 ZIP 提交到 Git；解压后的 EXE、.godot 缓存及日志均被忽略。

首次进入选择填海总量；有有效海岸版存档时自动续玩。暂停菜单可以重新选择规模，原旅程先备份。

## 四种心愿

地图为方形，西侧为连续大陆，东侧依次为浅海、远海、深海。金色方框标记本次可活动范围，边界外的陆地和海都被流动迷雾遮住，不能飞入或投石。

| 填海总量 | 地图网格 | 世界边长 | 陆地格数 | 山数 | 初始飞速 |
| --- | --- | --- | --- | --- | --- |
| 100,000 石 | 12×12 | 48 | 60 | 6 | 5.50 |
| 1,000,000 石 | 24×24 | 96 | 240 | 18 | 7.78 |
| 10,000,000 石 | 48×48 | 192 | 912 | 60 | 11.00 |
| 100,000,000 石 | 96×96 | 384 | 3,648 | 180 | 15.56 |

每格边长 4 个世界单位。浅海每格需 **10～100 石**，远海 **100～5,000 石**，深海 **5,000～50,000 石**。格子需求有变化，生成时校准为所选总量。山体总储量为目标石量的 120%，陆地还有可以刷新的散石。

## 操作

| 操作 | 按键 |
| --- | --- |
| 按画面方向飞行 | WASD / 方向键 |
| 升高飞越山体，松开下降 | 按住空格 |
| 分次采集、拾回落地石堆、与穿山甲对话 | E；按住连续采集 |
| 投向当前海格或同纬度岸边 | Q / 底部投石按钮 |
| 指定视野与射程内的落点 | 鼠标左键 |
| 全图俯瞰 / 返回随行视角 | Tab / 顶部全图按钮 |
| 随行视角缩放 | 鼠标滚轮 |
| 升级负重、采集、射程、飞速 | 左侧升级页签 |
| 收起 / 展开升级与神器栏 | U / 顶部升级按钮 |
| 操作说明 | F1 / 顶部帮助按钮 |
| 暂停、保存、重新选择规模 | Esc |
| 静音 | M |

顶部只常驻石子、负重、修行和填海进度。左侧升级显示当前值、升级后的值与价格，神器放在同一栏的另一页；按 U 可收起整栏。地图信息仅在 Tab 全图模式展开，底部根据附近目标显示采集或对话。普通采集和投石只更新数字，升级、神器等进展才显示短暂提示。

投石要求落点在可活动地图内、能被看见，并且处于精卫的水平射程内。**初始射程 4，金色圆圈表示范围**。鼠标、Q 和 Tab 全图均遵守相同距离限制；超出时不会消耗石子。采矿后需要将石料运近海岸再投放，升级投石后可以减少搬运距离。向大陆投石留下可拾回的石堆，只有填入海里的石子增加修行。靠近目标、降到低空才能采集或对话。

## 修行节奏

初始负重 **32 石**，每次采集 **10 石**，通常四次装满。负重和采矿每阶约翻倍，采矿同时提升穿山甲的开山速度。同级时，整个升级范围内保持 3～4 次采集装满背包。

以满载投海、不购买羽翼或投石射程、无神器为基准，负重与采矿成套提高一阶：

| 当前阶数 | 先升负重 | 先升采矿 |
| --- | --- | --- |
| 0 → 1 | 6 趟 | 8 趟 |
| 1 → 2 | 8 趟 | 10 趟 |
| 5 阶以后 | 约 18 趟 | 约 24 趟 |

神器会缩短这个周期。填海效率是“每趟携带量和采集量”的近似翻倍；实际每分钟效率还受探索、库存和是否满载影响。每投进海里 1 石获得 1 修行，可用于升级。

飞速随地图边长的平方根增长，每阶羽翼增加初始飞速的 8%，共 6 阶；不会每次翻倍。

投石射程按 **4 → 5 → 6.5 → 8 → 10 → 12.5 → 16 → 20 → 24 → 30 → 36** 增长。四档地图的上限分别为 **10、16、24、36**。首次升级需 96 修行，后续价格逐阶增加，保留探索与搬运的意义。

## 山与神器

全地图只有一只可对话的穿山甲。累计填海 **128 石**（初始满载约 4 趟）后自动开始开山，按储量从小到大依次开采。同一时间只挖一座，完工后自动转往下一座，无须逐山对话。未达到门槛时，在橙旗旁按 E 可查看还差多少石。整座挖完才留下全部有限石料，随后按 E 分次搬运。第一座青岚山产出 1,024 石，更远的山储量和体积逐渐增大，并按实际山脚范围留出间距。山形包括圆丘、尖峰、双峰、长山脊和层叠岩山；开采时从顶部逐步削低，开完后成为有限碎石场。**石料搬空后，石堆消失，该山不能重新开采**，原山址也不会生成刷新散石。

前三座山分别埋有三件神器，具体埋藏深度随种子生成并保存：

- 神农石篓：负重和每次采集量增加 20%。
- 乘风羽：飞速增加 15%。
- 开山印：穿山甲开山速度增加 25%。

每处陆地散石采集一次就消失，14 秒后重新出现。每次获得至多当前采集量，背包差少量装满时只补足空位；满背包不会消耗散石。通常需移动到 3～4 处散石才能装满。山体石料不刷新。满海格的余石自动铺向邻格，全海完成后多余石子留在背包。

## 声音

采石使用短促的石粒碰撞音，投石先有掠风声，约 0.48 秒落下时再根据海面或陆地播放水花、石块落地声。形成新陆地、升级、开山解锁、山体挖完、神器出土和完成心愿各有对应音效。常用动作有三种音色变体及轻微音高变化，避免连续采集时总是同一声。

背景是低音量的立体声海浪，海岸附近稍明显，深入大陆或远海逐渐变轻，对话和暂停时压低。按 **M** 立即静音或恢复；恢复后不会补播静音前尚未落下的石子声音。连点音效有冷却和数量上限，神器与完成提示拥有较高优先级。

音频全部由项目内工具合成，无外部录音依赖。原始 WAV 与导入设置在 assets/audio，使用 Python 运行 tools/generate_audio.py 可重新生成，不需要在游戏启动时合成。

## 保存进度

每 15 秒、解锁开山、完成心愿和正常关窗时保存，也可手动保存。暂停、对话和关闭游戏期间不生产；没有离线收益。

Windows 存档：%APPDATA%/AzVGames/Jingwei/coast_journey.json，备份为 coast_journey.json.bak。旧版 journey.json 保留，不会套用到新数值中。选择新的旅程会保存并归档当前旅程，再创建新地图。

本次存档版本为 3，会自动兼容之前的海岸版存档：填海进度、修行、已购升级、携带石料、山体库存和神器保留，山体位置与散石点重新留出安全间距，新增投石等级从零开始。保存时仍保留旧文件备份。旧存档如果已经开过山，保留解锁资格；原先多座山的未完工进度也保留，今后只由这只穿山甲按储量顺序接着挖。

存档保存生成后的地图、山体、神器计划、石料、修行、升级、投海进度和刷新计时。主文件损坏时尝试上一份有效备份；两份均损坏时不会自动覆盖，重开前仍先保留副本。

角色和场景目前是程序生成的低多边形模型。尚无正式美术、任意挖洞的体素系统、自动搬运和发布安装包。数值属于可玩原型的第一轮标定，后续可按试玩节奏调整。
