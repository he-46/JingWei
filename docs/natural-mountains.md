# 自然山体：固定格子、随机山形与连续岩面

本次新增的自然山体用于新旅程。已有 v3 存档没有 `terrain_version`，仍按原来的美术模型显示；不会读档后换山或改动已挖进度。新旅程保存世界种子和山体生成版本，读档重新生成相同格子分布。正式新旅程随机选择种子，美术样板和关闭保存的测试保持固定种子。

## 在 Godot 中看和调

打开 `scenes/art/natural_mountain_preview.tscn`，选根节点。在检查器调整 `Mountain Seed`、`Stones`、`Mining Progress`，3D 编辑区会更新四种山形。按 F6 可以运行预览，R 更换种子，左右方向键调整开采进度。这里使用正式游戏的生成器，不是另一套示意图算法。

在游戏中，从暂停菜单开始新旅程即可体验自然山体；原旅程会按现有流程备份。直接继续旧存档仍看到旧山形。

## 1. 储量决定格子数量

核心实现：`scripts/mountain_field.gd`。

```gdscript
const UNIT := 0.25
const STONES_PER_CELL := 64
total_cells = ceili(float(stones) / STONES_PER_CELL)
```

所有山共用 0.25 米的逻辑格子，一整格对应 64 颗石子。最后一格可以不满。例如 1025 颗石头占 17 格，最后一格只有 1 颗。资源账本仍以整数石子为准，不会向上取整多送石头。

`cells[i]` 保存某一列的整数 X/Z 坐标，`heights[i]` 保存这列叠了几格。底部始终从地面开始。因此没有必要给内部每个格子创建 Node3D，也不用保存百万个方块对象。山体节点的缩放始终是 1；允许绕 Y 轴旋转。

此前网页预览中的单位是示意参数，正式地图统一采用上述尺寸。储量变化不改变这个单位。既有山地保留区仍作为最大占地边界，避免山体侵入海岸通道、植被或其他山。占地达到边界后增加高度；地图总石量和山的产量分配不变。

## 2. 种子决定山形，整数分配保证石量

`generate()` → `_build()`：

1. 用世界种子和山编号生成本山种子；选择偏峰、双峰、曲折山脊、台地之一。
2. 在固定网格上计算候选列，随机参数影响长宽比、偏斜、边缘起伏和山脊弯曲。`FastNoiseLite` 增加局部起伏。
3. 从中心做四邻域遍历，只保留连通的山脚。每列至少放一个地面格子，小山只保留能负担的连通前缀。
4. 计算每列的形状权重，给剩余格子按权重分配高度。先取整数部分，再按小数余量从大到小补齐，使所有列高度之和恰好等于总格数。
5. 做最多 16 轮局部坡面调整：相邻柱过陡时，将高柱的整格移给低柱。交替遍历方向减少方向偏差。这一步不增减总格数，也不移走任何列的地面格子。

这是保证落地、连通并抑制尖刺的简化规则，不是岩石力学仿真。它不生成洞穴、悬挑和天然石桥；这些需要真正的三维密度场及支撑判断。

## 3. 逻辑方格如何变成岩面

`surface()` 从剩余列高生成 `ArrayMesh`：每个格点的高度取周围四列的平均值；水平位置按坐标和种子做有限扰动。相邻格面读取同一个顶点，边界补上降至地面的面片，避免接缝和浮空边缘。

每个四边形拆为两个三角形，交替选择对角线，并给三角形独立法线，呈现低多边形岩面。颜色随高度轻微变化以表现岩层。平滑只作用于显示表皮，不参与资源结算，因此显示体积并不严格等于格子体积。

`scripts/world.gd` 将同一份网格交给 `ConcavePolygonShape3D`，可见的山谷也是碰撞中的山谷。新山不再用八层圆柱近似碰撞。加载结束前等待物理系统接收网格，避免刚进入地图时射线穿山。

## 4. 开采、更新和保存

`removed_cells(work)` 把开采进度换算成已移除的完整格数。未满 64 的开采进度不缩小格子；最后一个不满格在山体完成时移除。

`remaining_heights()` 用二分搜索找到当前开采层，整层移除高处格子，层内按 Z/X 固定顺序推进。因此一次推进 100 秒和分成多次推进，最终几何结果相同。它不遍历所有内部方块。

世界只在完整格数变化时重建正在开采的山，不会每帧重建全部山。完成时删除岩面和碰撞，原有 `JWState.tick()` 一次性把该山全部产量记入碎石场；搬空后不能再次采集。神器、负重、采集速度和填海结算沿用原规则。

山形数据在加载阶段的后台线程准备，网格和物理对象在主线程创建。存档只增加每山的 `terrain_version: 1`，不保存网格或每个方块。生成规则或噪声依赖发生不兼容变化时，必须增加生成版本并保留旧实现，不能直接覆盖 v1 算法。
