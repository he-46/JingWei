# 精卫填海：上线美术任务包

创建日期：2026-10-14。适用工程：Godot 4.7.2，Windows 64 位，当前 Compatibility 渲染器。

本文把美术升级拆为 10 个可独立交付的任务包。当前仅完成任务拆分，以下任务尚未实施；本文中的模型数量、面数和性能要求均为计划或初始预算，不代表已经达到。

## 目标与执行原则

目标是形成适合小体量独立游戏上线的风格化 3D 画面：赤冠青羽的精卫、覆瓦状鳞片的穿山甲、有岩层结构的群山、可以观察填海变化的海岸。采用手绘质感、清楚的轮廓、克制的材质细节与柔和光照，并与现有米白、草绿的简洁 UI 协调。

先完成一段能实际游玩的最终质量海岸，再扩展整张地图。以正常游戏镜头下的辨识度、重复操作的舒适度和实机表现为验收依据；建模软件中的特写渲染只作辅助。

每次执行一个任务包时：

1. 读取本文件的共同约束、该包内容，以及已完成依赖的交付记录；确认当前工作区已有变更。
2. 先检查现有实现，再实施该包范围。依赖未完成时推进不依赖它的部分，并准确记录剩余依赖，不虚报完成。
3. 完成对应的引擎内检查；保存可复现的验证方式和结果。
4. 更新任务状态及交付记录，再按当前项目流程提交 GitHub。每个任务包尽量独立提交，便于回退。

任务包不是新建的聊天任务或定时任务，也不表示已安排多人同时执行。

## 共同约束

| 项目 | 必须保持的行为 |
| --- | --- |
| 世界 | 方形活动范围，连续大陆海岸；边界外陆地和海被迷雾遮挡，不可进入或投石。 |
| 难度 | 10 万、100 万、1000 万、1 亿石四档目标及各档实际填海需求继续成立。 |
| 资源 | 使用“修行”；每次实际投入海里的石子产生对应修行，视觉效果不生成资源。 |
| 开山 | 一只穿山甲，累计填海 128 石后解锁，按储量从小到大逐山开采，整山完工后产生有限库存。 |
| 采集 | 陆地散石采集一次消失并按原规则刷新；山体库存搬空后不再产石。 |
| 投石 | 视野、地图边界、射程和背包校验继续由现有规则决定；动画和模型不改变可投距离。 |
| 保存 | 保留现有存档及备份机制；旧档进度、修行、库存和神器不因美术更新丢失。 |
| UI | 保留当前简洁信息层级，不重新堆叠常驻标语、标签或面板。 |
| 分发 | 保持当前临时版 Play.cmd 可用；模型导入不得要求玩家另行安装 Blender。 |

默认沿用现有 Compatibility 渲染器。需要更换渲染器或改变上述玩法时，先记录必要性、兼容影响及替代方案，作为超出本任务包范围的变更处理。

## ART-00：风格规范与现状基线

**目标：** 固定可执行的美术方向，建立更新前后的比较标准。

**输入与入口：** scripts/models.gd、scripts/world.gd、scripts/hud.gd、现有 shaders、project.godot、docs/architecture.md。

**工作内容：**

- 记录四档地图的固定种子和可复现镜头：出生海岸、山脚近景、大陆深处、深海、全图。
- 保存现有实机截图及基础运行表现，记录硬件、分辨率和画质设置。
- 制定颜色、轮廓、材质、光照、模型尺度和细节密度规范。明确精卫的赤冠青羽、穿山甲的鳞甲长尾、岩石与可采石料的区分方式。
- 明确正常游戏缩放范围；对主角、散石、NPC 和目标落点设置可辨识的对比关系。
- 定义模型与动画的初始预算，并记录参考设备和拟支持的最低设备。尚未确定最低配置时保留为待验证项。
- 收集使用的参考资料和素材来源；任何外部资产必须记录出处及可分发条件。

**交付物：** docs/art/style-guide.md、docs/art/baseline.md、第一版资产清单、基线截图及复现步骤。

**验收：** 同一场景可按记录重新生成；规范覆盖角色、山石、植被、水面和 UI 的关系；性能记录具有设备与设置上下文；没有把目标帧率写成已测结果。

**范围边界：** 本包不批量制作模型，不修改玩法数值。

## ART-01：资产导入与表现层接口

**目标：** 正式模型能够替换程序模型，且不增加玩家运行依赖。

**工作内容：**

- 建立 Blender 源文件 → GLB → Godot 预制场景的可复现流程；游戏加载导出的 GLB，源文件排除自动导入。
- 约定朝向、单位、原点、应用缩放、骨骼和动画命名、材质与纹理目录。
- 建立精卫、穿山甲、山体的最小表现接口，并用简单占位模型验证。精卫接口覆盖朝向、移动、高飞、负重、采集和投石；穿山甲覆盖工作状态、目标和完工；山体覆盖储量规模、开采进度与剩余库存。
- 把 world.gd 对 WingLeft、WingRight、Load 等现有节点的直接操作改为明确接口，避免正式骨骼导入后失效。
- 约定模拟与显示的关系：采集、投石结果由 state.gd/main.gd 结算，视觉接口接收结果；动画帧事件只触发视觉或声音，不重复结算资源。
- 由逻辑统一提供尺寸和碰撞参数，避免模型显示、站位与采集范围各算一套。

**交付物：** docs/art/asset-pipeline.md、docs/art/visual-contract.md、可运行的导入示例、必要的表现接口及有意义的集成检查。

**验收：** 全新源码副本不安装 Blender 也能导入并运行；精卫移动、采集、投石和穿山甲工作正常；现有测试通过；资源总账、碰撞与存档格式保持兼容。

**范围边界：** 本包完成接口与流程，暂不以占位模型的外观作为最终美术成果。

## ART-02：精卫模型与动作

**目标：** 形成具有辨识度、适合长时间观看的主角。

**工作内容：**

- 制作连续的身体、头部和喙，分组设计翅膀与尾羽，明确赤冠、青羽、浅色腹部的比例。
- 完成必要的 UV、材质、骨骼与权重；在实际俯视镜头下调整体型和羽翼展开尺度。
- 制作至少六类动作：待机、飞行、转向、采石、负重飞行、投石；合理使用混合与叠加，不要求每个变化单独制作整段动画。
- 携带表现分为空载、轻载、满载等有限档位，按背包占比显示，不按百万颗石子创建实体。
- 处理转向衔接、连续采集、连投、升降和暂停恢复；让动作与现有音效的起手、落点时序协调。

**交付物：** 精卫源模型、GLB、材质、角色场景、动画配置、预览场景和正常镜头实机记录。

**验收：** 正常缩放下能认清朝向与负重状态；转向和拍翼无明显穿体、拉伸或闪烁；投石动作与实际操作一致；任何动画中断都不增减资源；更换地图后不残留旧动作事件。

**范围边界：** 本包不加入新角色、皮肤商城或成长数值。

## ART-03：穿山甲模型与动作

**目标：** 唯一 NPC 具有鲜明外形，工作状态可观察。

**工作内容：**

- 制作长吻、弓背、长尾与前爪，鳞片采用清楚的大块分组，远距离仍保留主要轮廓。
- 完成待机、移动、挖掘、完工动作，补齐与 ART-01 接口的连接。
- 挖掘时面向当前工作面，配合小幅身体发力和尾巴平衡；避免只让整个模型上下晃动。
- 换山时只保留一个 NPC。可使用短暂离场和入场过渡；若实现移动表现，逻辑目标仍以现有规则为准，避免对话点与角色分离。
- 待机、尚未解锁、开采中和全部挖完的表现分别可识别。

**交付物：** 穿山甲源模型、GLB、材质、角色场景、动作与工作状态集成记录。

**验收：** 四档地图均只有一个穿山甲；换山后模型、采集/对话距离和地图标记一致；挖掘动作不穿进整座山；暂停时工作动画与生产状态一致；旧存档载入能显示正确工作状态。

**范围边界：** 本包不改变解锁门槛、开采顺序，不新增多个工人或复杂寻路玩法。

## ART-04：样板山体与开采变化

**目标：** 一座山从完整到搬空有清晰、自然的变化，可扩展到后续山型。

**工作内容：**

- 先制作一套有岩层与明确山脚的样板山体，并配套开采阶段和碎石场。
- 表现完整山体、岩层暴露、分层开采、碎石场、空山址；按连续工作进度驱动阶段或过渡，明确各阶段如何衔接。
- 开采中的碎石与扬尘属于效果，不可提前采集。整山完工时才将规则层生成的库存显示为碎石场。
- 山体尺寸从储量及地块允许尺寸派生；在同等约束下更高储量应有更大体量。避免无上限按真实石子体积放大，保留通道与山脚间距。
- 库存降低时缩小或减少碎石组；库存为零时移除可采资源表现，留下不具有采集能力的遗迹。
- 更新阶段变化中的碰撞、可飞越高度及视觉边界。保留明确的低成本碰撞方案，不将每块装饰碎石变为刚体。

**交付物：** 一套样板山体及阶段资产、阶段控制器、储量到尺寸的约定、碰撞同步实现、阶段复现场景。

**验收：** 0%、约 25%、50%、75%、完工、搬空六种状态可复现；显示与碰撞匹配；全额库存只结算一次；搬空山无法再产石；读档后恢复对应阶段；原采集范围与射程规则仍成立。

**范围边界：** 本包不制作全部山型，不引入任意挖洞的体素系统或逐石物理模拟。

## ART-05：样板海岸、水面与灯光

**目标：** 为正式角色提供统一、有层次且可读的环境。

**工作内容：**

- 制作一段有宽窄变化的沙滩、岩岸与浅水石，增加少量草丛、灌木及适合海岸的树木样板。
- 先保持现有大陆/海格逻辑边界；通过边缘网格和材质变化自然化视觉轮廓，控制偏移，避免看起来是陆地却按海域处理。
- 调整浅海、远海、深海的颜色过渡与波纹，加入受控的岸边泡沫和湿润边缘。
- 统一主光、环境光、阴影和材质粗糙度，保证精卫、石料和射程指示能从背景中分离。
- 为填海生成的陆地提供石质表面和接水边缘；依据已有海床与填充数据变化，保持相邻区块接缝连续。
- 改善边界迷雾与场景衔接，活动范围内保留可读性，范围外继续遮挡。

**交付物：** 样板地表与植被、共享材质、水面/海岸表现、灯光配置、固定镜头对比。

**验收：** 正常缩放与全图均无明显拼缝、闪烁、穿水或硬切层；连续填满相邻海格后岸线正确更新；采集通道清楚；边界外保持不可达且被遮挡；效果在当前 Compatibility 渲染器中运行。

**范围边界：** 本包不把地图改为海岛，不新增昼夜天气系统，不以装饰改动海格需求量。

## ART-06：采集投石反馈与神器

**目标：** 完成重复操作的反馈，以及少量重要事件的视觉奖励。

**工作内容：**

- 为采集、投出、落水、落地、填成陆地、开山完工建立可复用效果，跟随实际事件触发。
- 沿用并校对当前投石飞行与约 0.48 秒落点音效时序。若调整动画时长，同步调整效果调度，不让画面与声音各用一个时钟。
- 制作神农石篓、乘风羽、开山印三件神器的模型及清楚的 UI 图标，统一两者的形状和配色。
- 神器出土提供短暂的局部高亮与展示反馈，详情继续放入现有神器页签，避免增加长期遮挡画面的面板。
- 为高频采集、连投和连续矿山事件设置效果数量上限；复用实例，暂停、静音、重选地图时按现有语义清理。

**交付物：** 效果资源与控制器、三件神器模型/图标、事件对应表、实机反馈记录。

**验收：** 成功动作才播放对应效果；超距与空包不出现成功投放；静音期间不补播旧落点声音；换地图后不出现旧效果；反复触发不会无限增加节点；神器加成仍只由状态层决定。

**范围边界：** 本包不重做整套 UI，不新增神器数值、掉落机制或强制暂停的长演出。

## ART-07：最终质量可玩样板验收

**目标：** 交付一段代表最终成品质量的可玩海岸，并确定是否具备批量扩展条件。

**工作内容：**

- 把正式精卫、穿山甲、样板山体、环境、反馈和简洁 UI 集成到真实主流程。
- 提供固定种子的样板入口，保持普通玩家流程可用；调试入口不影响正式存档。
- 完整走通出生 → 拾石 → 投海 → 解锁开山 → 神器出土 → 完工 → 搬空 → 新陆地形成。
- 分别观察正常镜头、小窗口、拉远镜头和全图；对照 ART-00 基线复核轮廓、材质、光照与信息密度。
- 记录问题的具体镜头与复现步骤，先解决阻碍玩法或显著破坏画面的缺陷，再进入扩展。
- 准备可游玩的样板、截图和短录像供评审；审美偏好未确认时如实保留，不将“功能测试通过”写成“美术已认可”。

**交付物：** 可运行样板、docs/art/vertical-slice-review.md、更新后的风格规范及资产清单、问题清单。

**验收：** 样板包含完整资源循环；没有占位关键角色或关键效果；无阻断操作的碰撞问题、明显角色破面或地表接缝；现有自动检查通过；画面与性能评审结论具有实际记录。

**阶段出口：** 样板达到已定义标准后才能批量制作 ART-08。若风格尚需修改，回到对应任务修正，避免将未定稿缺陷复制到所有模型。

## ART-08：全地图资产扩展与性能优化

**目标：** 将样板扩展为完整资产集，并使最大规模地图保持可用。

**工作内容：**

- 将山体扩展至约 6～8 种具有独立轮廓的基础山型，每种接入开采和搬空表现。
- 完成约 6 种散石形态、3 组碎石场组合、3 种树形、2 种灌木和2种草丛。具体数量可据重复感与画面密度调整，资产清单须记录实际数量。
- 按地区及地块约束组合资产，使用有限的旋转、尺度和颜色变化，保留资源位置与碰撞的一致性。
- 为重复物体复用网格与材质，并按空间区域拆分批量绘制；为远景设计简化模型或可见距离。
- 按距离简化角色动画、植被运动、粒子和阴影，给全图模式设置独立的显示细节预算。
- 保留现有存档中的山型标识含义；若扩展模型映射，建立明确兼容表，避免旧档加载后碰撞或尺寸不可达。
- 在四档地图测试正常游戏、最大海域改造、密集山体、事件集中触发和全图场景，记录帧时间、峰值内存及主要耗时。

**交付物：** 全量模型/材质集、资产清单、LOD/分区策略、兼容映射、docs/art/performance-report.md。

**验收：** 四档地图均能正常游玩；大山与邻山/道路不穿插；近景变化丰富，拉远无明显突然跳变；旧档可继续；以 ART-00 指定设备和设置评估 1080p、60 帧目标，同时报告较慢场景和未覆盖设备。未达到时给出可复现瓶颈与降级方案，不宣称达标。

**范围边界：** 本包不无限增加装饰数量，不用切换高开销渲染方案替代实测优化。

## ART-09：美术版本发布验收与交付

**目标：** 形成可交付的美术升级版本，并清楚区分已验证范围和上线前剩余事项。

**工作内容：**

- 检查所有正式模型、纹理、动画、材质引用与字体显示，清理运行路径中的样板占位和缺失资源。
- 用全新源码副本执行 Play.cmd/Test.cmd，确认正式资产能够重新导入；继续验证没有 Blender 环境也可运行。
- 完成四档地图、旧存档、新开局、重选地图、暂停、静音、全图及完成填海的回归检查。
- 整理各类源文件、生成或导出步骤、外部素材来源及许可声明，检查 Git 跟踪文件与下载体积。
- 生成实机截图与简短演示材料，保证宣传画面与可玩的版本一致。
- 编写美术更新说明、已知问题、回滚方法，以及准确的测试设备和环境范围。
- 核对发布前缺口。正式独立 EXE 打包、商店页面、平台审核等单独列项；如未完成，不将本包状态表述为“整个游戏已上线”。

**交付物：** 完整美术版本提交、更新说明、资产来源与许可清单、docs/art/release-checklist.md、可复现的验证记录。

**验收：** 目标下载版本可启动；自动检查通过且人工实机检查有记录；旧进度不丢失；无阻断玩法的美术缺陷；许可材料齐全；性能与兼容性声明限于实际验证范围。

## 每包交付记录模板

执行时创建 docs/art/deliveries/ART-XX.md，填写以下内容：

| 字段 | 要求 |
| --- | --- |
| 任务与状态 | 包 ID、日期、当前状态。 |
| 实际变更 | 本包完成的资产、代码及行为变化。 |
| 使用方法 | 入口、操作及依赖；可复现的预览方式。 |
| 验证 | 自动检查、人工实机检查、设备和设置，明确通过或未通过。 |
| 视觉证据 | 截图/录像位置及对应场景；忽略的本机产物须附生成方式。 |
| 兼容性 | 存档、碰撞、旧资产引用与分发的影响。 |
| 剩余问题 | 尚未完成、受阻或超出范围的事项。 |
| 版本 | 提交标识与回退边界。 |
